## 修正方式

原模組只修改 `eqb0(Double, boolean)` 建構輸入。原始 DEX 顯示它由 `dqb0.b(User)` 建立，再由 `dqb0.a(User)` 及多個課程／預覽呼叫端消費。小型方法可能被 Android 執行期內聯，造成 hook 註冊成功但實際不經過原方法。這是本次採取處理的候選原因，尚未經新版實機驗證。

0.3.2 保留原本只乘一次的倍率邏輯，並在精確版本碼、版本名及 base SHA256 匹配時，向 53 個直接 XP 呼叫方法請求去最佳化。完整類別、方法、參數及回傳型別都由原始 DEX 產生並核對；不只按方法名稱套用，也不改全域編譯設定。一般 Java 反射無法取得靜態初始化器，`ywr.<clinit>` 不包含在這 53 個方法內。

使用 LSPosed 可選的 `XposedBridge.deoptimizeMethod(Member)`，並保留舊版 API 依賴。框架缺少此方法時獨立記錄 unavailable，不阻止其他功能註冊。逐個方法的請求失敗會記錄方法名稱及錯誤類型。請求返回不代表底層一定成功去最佳化，也不代表倍率已命中。

原理與 API 依據：[LSPosed 官方 XposedBridge 原始碼](https://github.com/LSPosed/LSPosed/blob/master/core/src/main/java/de/robv/android/xposed/XposedBridge.java)。另已直接核對本機官方 2.2.1 (7912) 下載包的 framework.dex 確有該方法；這不是手機執行成功的證據。

本版保留 0.3.1 的唯讀診斷與既有開關。沒有修改 HTTP 本文、偽造總 XP 或覆寫伺服器回應。其他功能邏輯未因本次 XP 修正而新增已完成的實機驗收結果。

## 實機下一步與判定條件

覆蓋安裝 0.3.2，維持只有額外 ×3，完整關閉再開啟 Duolingo。先確認日誌包含新版標記 `Module 0.3.2-alpha` 與 `XP caller deoptimization requested`，再測一堂課。

1. 若出現 `XP inputs reached: ... effective multiplier=3.0`，表示倍率入口已恢復命中；有原生加倍時有效倍率可能更高。
2. 比對 `XP serialization completed` 是否仍為 1.0／false；若仍未變，需繼續追蹤值在哪個呼叫鏈被覆寫，不能宣稱已修好。
