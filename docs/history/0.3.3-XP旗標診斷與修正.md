## 找到的資料鏈

原始 Duolingo 6.103.6 (2488) 的 `vu10` 分別呼叫：

- `dqb0.a(User)`：取得有效倍率；0.3.2 已確認能變成 3.0。
- `dqb0.d(User)`：依實際道具取得是否啟用加倍；此次仍為 false。

兩個值分別傳入 `fs7.a` 的第 10、11 個參數，再建立完成課程模型 `com.duolingo.core.session.c`，存為 `i`（double 倍率）及 `j`（boolean 加倍旗標）。`ls7.serialize` 讀取兩者，建立 `CompletedSessionSurrogate`，之後由 `ms7` 編碼成已觀察到的倍率與 hasBoost。

先前只修改倍率輸入，沒有同步建立完成課程資料時的旗標。這是目前已觀察並可核對的狀態不一致；尚無證據能斷言它是伺服器只計標準 XP 的唯一原因。

## 本版修改

0.3.3-alpha (versionCode 6) 保留已確認能命中的倍率修改與 53 個呼叫點去最佳化。

新增精確樣本限定的完成課程工廠 hook：僅在模組啟用且額外倍率不是 1 時，若已算出的倍率有限且大於 1，將該筆資料的 hasBoost 設為 true；原本 true 保留。只修改工廠的旗標參數，不改倍率、不再乘一次、不更改 xpPromised、expectedXpGain、課程答題內容或預設遮罩，也不建立額外道具。其他版本不套用此固定位置。

新增 `XP session inputs reached` 記錄，會顯示倍率及旗標修改前後值。既有編碼、HTTP 與摘要診斷保留，繼續排除帳戶識別、網址、認證與完整本文。
