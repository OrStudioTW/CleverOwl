# 0.3.0-alpha：日誌診斷與全功能檢查

日期：2026-10-29（Asia/Taipei）。本次已完成日誌定位、參考模組 XP 邏輯研究、所有現有功能的實作檢查及新版打包；新版尚未在使用者另一支測試手機上執行，不能宣稱所有功能正常。

## 已確認的實機失敗

來源為使用者提供的 `LSPosed_20261029_131154.zip`。測試環境日誌宣告 LSPosed v2.0.4 (7741)，Duolingo 6.103.6 (2488)。沒有將完整日誌、裝置識別或其他 App 的資料放入交付包。

- 12:13～12:18：模組記錄 Disabled or configuration unavailable，符合後續使用者發現尚未開設定的情況。
- 12:37：舊版會員 hook 有註冊紀錄，隨後 DEX-based features 出現 UnsatisfiedLinkError。
- 12:58：設定已成功讀取，記錄會員 MAX、timer=true、XP=10，隨後立刻再次出現 UnsatisfiedLinkError；沒有後續會員／XP／計時註冊或命中紀錄。這是該次匯出中最後捕捉到的設定，不否定使用者另曾測試 ×3。

因此至少已證明：功能引擎在註冊前失敗，按鈕沒有套用倍率不能用單改預估文字解決。舊版只輸出錯誤類型，無法從這份日誌再確定完整 linker 訊息。先前以資料鏈推測應顯示 75，不是實機成功證明。

## 參考模組研究與引入

參考 APK SHA-256：`93f355ffa593e7dca1d962ccdb76b53dc072e77e9f234e8c0ee789497b2be7bc`。已反編譯其 Java／DEX 並解出相關字串，native 部分未完整還原，未安裝或執行參考 APK。

- 會員在 User 建構前修改參數，三種限時練習在模型建構前調整初始時間；0.2 已依真實樣本實作，本次保留並逐項核對。
- XP 類別 `com.owl.auxiliary.g` 的 hook 包含固定回傳 5.0，以及以反射設定 `CompletedSession.xpPromised` 為 100。這不等於使用者要求的額外 ×3，也不能證明其舊方法在目前版本生效。本次維持共用 XP 輸入的可選倍率，不照搬固定會話 XP 覆寫。
- 參考 APK 的 arm64 DexKit library 為未壓縮；0.2 是壓縮的。兩者 ELF 系統依賴均未顯示缺少另外的 C++ shared library，且 load segment 均為 16 KB 對齊。因此沒有任意加入不需要的 shared library。

新版改成未壓縮且 ZIP 16 KB 對齊，正常 native 搜尋失敗時，以 LSPosed `initZygote` 提供的本模組 APK 路徑及正確程序 ABI 明確載入。這是針對已確認載入失敗的修正設計；不能把包裝差異單獨當作唯一根因已證實。

更直接的處理是：對版本、版本碼、base SHA-256 全相符的既有樣本，使用已經原始 DEX 檢查的類別／方法直接註冊，略過 native 掃描。這條路徑涵蓋會員、XP、預估觀察、加倍時間與所有現有計時 hook，不再讓共同 native 載入點阻擋整組功能。未知 APK 仍須通過動態唯一特徵與結構匹配。
