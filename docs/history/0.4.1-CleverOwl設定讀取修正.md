# CleverOwl 0.4.1 設定讀取修正

已針對 0.4.0 的跨 App 設定解析失敗製作新版，實機驗收待安裝後進行。

## 診斷證據

讀取已連線裝置最新匯出的 `LSPosed_20261029_180816.zip`。裝置安裝模組 0.4.0-alpha／code 8，Duolingo 6.103.6／2488。日誌確認 18:07:42 CleverOwl 入口已插入隱私設置下方；18:07:43、18:07:48 均出現：

```
Failed to find provider info for dev.local.duolingoxposed.settings
CleverOwl settings page unavailable: IllegalArgumentException
```

手機套件檢查確認 SettingsProvider 有註冊、套件已啟用。失敗發生在從 Duolingo 解析 provider，尚未執行 Screen 建構；與套件可見性過濾一致。原先提示一律要求確認 LSPosed，未區分真正失敗階段。

## 修改

移除 provider，改由明確指定的 SettingsExchangeActivity 在模組程序讀寫六個設定。Activity 使用 Theme.NoDisplay，於 onCreate 完成或失敗後立即 finish，沒有另開設定介面。Duolingo 中的設定畫面仍使用原生 Compose 元件。

以 startActivityForResult 建立 Android 提供的 calling package，檢查確為 com.duolingo 且原版簽章吻合後才存取共享偏好；不信任 Intent 提供的來源宣告。ResultReceiver 返回僅包含六個功能設定。保留嚴格欄位／型別／選項驗證、commit 與讀回核對。

加入 10 秒逾時與忽略晚到回覆、避免連點開啟、儲存快照與期間禁止選項改動。讀取、頁面初始化與儲存錯誤分開處理；日誌包含例外類型和呼叫位置，不包含例外訊息、帳戶、網址或認證。

Android 官方明確允許啟動不可查詢套件的 Activity；服務與 provider 的解析沒有這項普遍保證。參考 [Android 自動可見性規則](https://developer.android.google.cn/training/package-visibility/automatic?hl=en)。不修改 Duolingo Manifest，不要求列舉全部 App 的權限。
