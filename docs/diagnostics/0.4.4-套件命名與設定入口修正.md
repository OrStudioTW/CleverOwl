# 0.4.4：套件命名與新安裝設定入口修正

查核日期：2026-10-30（Asia/Taipei）。版本：0.4.4-alpha／versionCode 12。

## 結論與證據

入口缺失的直接原因是 0.4.3 使用整份 base APK 的 SHA-256 作為內嵌設定與固定方法 profile 的門檻。新設備的程式與資源內容相同，但 APK 容器雜湊不同，因此被誤拒絕。全新安裝的總開關預設為關閉；入口又被跳過，導致使用者無法進入設定啟用功能。這不是日誌顯示的 LSPosed 注入失敗，也沒有證據支持是隱私列渲染本身故障。

使用者提供 `LSPosed_20261030_230357.zip`，SHA-256：`387b972914a1ea807b38a29dfe27e85c47f88a8e0e2cc0a0ae06690ec39dee06`。其中模組日誌於 22:57:42、22:58:28、23:00:57、23:01:12、23:02:17 的五次啟動都顯示：

```text
CleverOwl 0.4.3-alpha; Target 6.103.6 (2488)
Native settings integration skipped: this APK profile has not been inspected.
```

作用域及模組載入資訊也確認舊套件已注入 `com.duolingo`。LSPosed 匯出 metadata 為 v2.2.1（7912）。第三行舊日誌宣稱設定仍可用，與前一行跳過入口矛盾；新版已修正。

對目前連接設備只讀查核及匯出 base APK：Android 16／API 36、arm64-v8a、Google Play 安裝的 Duolingo 6.103.6（2488）、已安裝 CleverOwl 0.4.3-alpha（11）。未安裝新模組、改設定、重啟 App 或操作課程。

| base APK SHA-256 | `30d915c7e55423f071157e6ce9064bae8cd7e65ed09bb99383bae505709f456c` | `c4350eb27637e821f1dbaebd9988f23f270b4bbe5118b59cc01048fb9ac71c89` |

由此可確認差異在 APK 容器層；未將差異細分為特定簽章區塊、壓縮或 ZIP metadata 成因，也未據此宣稱其他版本相容。原始 ZIP、設備匯出及逐檔比較保留於 Git 排除的 `work/`，不放入來源交付。

## 修改

- `applicationId`、namespace、Java package、來源／測試路徑、Xposed 入口、自身 scope 與設定交換目標統一為 `tw.orstudio.cleverowl`；同步更新封裝與分析工具。
- 新增 `ApkProfile2488`：在既有官方簽章檢查後，驗證版本及全部 10 份 DEX、Manifest、資源表的 SHA-256。缺檔、改動、額外 DEX 或重複受檢項目均拒絕；僅容器差異可接受。此門檻同時用於內嵌設定與原先的固定功能 profile，避免修好入口後仍誤走未知 APK 分支。
- 內嵌入口仍於總開關判斷之前註冊。日誌區分 profile 不匹配、hook 註冊成功與入口不可用；註冊成功仍不宣稱已顯示或功能生效。
- 保留沒有桌面圖示、沒有獨立設定 UI 的設計；唯一 Activity 仍是無畫面設定交換元件。prefs 名稱 `features` 與 schema 1 不變。

## 自動驗證

- JDK 21／SDK 36／Gradle 8.13，離線 assembleDebug、testDebugUnitTest、lintDebug 成功；45 項單元測試通過，lint 0 錯誤、4 警告。
- 新增 6 項 profile 回歸測試：不同容器同內容可接受；每個程式／資源項目被改動或缺失均拒絕；新增 DEX、錯誤版本、同版本但未分析內容均拒絕。
- 以實際 runtime profile 函式在 JVM 讀取兩份原版 APK，兩份皆通過；不是僅比對硬編碼字串。
- 兩份原版 APK 分別重新執行 160 項原始 DEX 斷言，均通過。
- 封裝核對套件 ID、版本、Xposed 入口及自身作用域、必要類別、舊套件類別缺席、無 launcher、無要求權限、APK 簽章及四 ABI 的 16KB 對齊。結果見交付目錄 `verification/summary.json` 與[本次摘要](../verification/v0.4.4/summary.json)。

首次受限環境建置因無法連接本機 Gradle 程序而失敗；允許本機程序通訊後同一離線工作成功，並未以失敗報告交付。原始建置記錄留在 `work/diagnosis-20261030/`。

## 安裝與人工驗收

套件 ID 改變後，Android 視為另一個 App，無法直接覆蓋舊套件；舊設定也不會自動搬移。建議依序操作：

1. 在 LSPosed 停用舊的 `dev.local.duolingoxposed`，避免雙重注入；不需要清除 Duolingo 資料。
2. 安裝 `CleverOwl-0.4.4-alpha-debug.apk`，在 LSPosed 啟用新的 `tw.orstudio.cleverowl`，確認 Duolingo 與模組自身作用域。
3. 完整重開 Duolingo，確認「設定 → 隱私設置下方 → CleverOwl」出現；總開關關閉時也應可進入。
4. 確認頁面開啟、設定儲存、重開保留、返回與原隱私入口正常，再逐項驗證原有功能。
5. 若仍沒有入口，匯出新的 LSPosed 日誌，核對版本為 0.4.4-alpha、profile 命中、native settings 註冊與 row rendered 訊息。
